## 一、装到手机主屏幕上

iPhone / iPad：

1. 用 **Safari** 打开上面的地址（必须是 Safari，Chrome 加不了）
2. 点底部中间的「分享」按钮
3. 往下滑，点「**添加到主屏幕**」
4. 右上角「添加」

之后桌面上会多一个图标，点开是全屏的，没有地址栏，和原生 App 看起来一样，也不会七天失效。

Android 类似：Chrome 打开 → 右上角三点 → 「添加到主屏幕」。

## 二、三个标签页

### 播放

- 顶部输入框粘贴地址，点「开始播放」
- 输入框里可以直接粘一**整段分享文案**（带标题、带提取码那种），它会自己把里面的网址挑出来
- 点「粘贴」按钮会自动读剪贴板并立即播放，省一次点击
- 支持 mp4 / mov / m4v 直链，以及 m3u8 直播流
- 播放器右上角有**全屏按钮**，点一下铺满整个屏幕，画面自动转成横向，再点退出
- 播放后视频下方有「加入列表」和「复制链接」
- 「最近播放」保留 20 条，每条右侧有两个按钮：`＋` 加入列表、`×` 删除

### 列表

- 收集你想连着看的视频，最多 50 条，同一个地址不会重复加入
- 点任意一条，就从那条开始**顺序连播**，一条播完自动跳下一条
- 正在播放的那一条会被橙色高亮
- 右上角「清空」一次性清掉

### 识别

粘贴一个地址，它会告诉你这是什么东西，以及能不能播：

| 判断结果 | 说明 |
| --- | --- |
| 视频直链 | mp4 / mov / m4v / webm，能直接播 |
| HLS 流 | m3u8，能直接播 |
| 网页地址 | 是页面不是文件，播不了，但可以新标签打开 |
| DASH / FLV | 浏览器原生不支持，播不了 |

**为什么这里的「识别」不能像 App 那样自动嗅探**：浏览器有同源策略，本页面的脚本读不到别的网站的请求，也探测不到别的标签页在下什么。这是浏览器的安全限制，不是没做。

所以这里给了一个折中方案：**视频地址提取器（书签小工具）**。把那段 `javascript:` 代码存成浏览器书签，在视频网页上点一下，它会在**那个页面内部**扫描 `<video>`、`<source>` 标签和已加载的网络资源，把疑似视频地址列出来供你复制。

用法：识别页 → 展开「视频地址提取器」→ 复制代码 → 新建书签，地址栏粘贴该代码 → 打开目标视频网页 → 点这个书签。

> 电脑上比手机上顺手很多。手机上 Safari 需要先在「设置 → Safari → 显示书签栏」里打开书签栏才方便点。

## 三、支持的格式

| 格式 | 能否播放 |
| --- | --- |
| `.mp4` / `.m4v` / `.mov`（H.264） | 可以 |
| `.m3u8`（HLS） | 可以，Safari 原生；其他浏览器用 hls.js |
| `.webm` | Chrome / Android 可以，iOS 不行 |
| `.mpd`（DASH） | 不行 |
| `.flv` | 不行 |
| YouTube / B 站页面地址 | 不行，那是网页不是视频文件 |

## 四、常见问题

**提示「这个地址不是浏览器能直接播放的视频格式」**
地址本身不是视频文件，或者链接已过期、需要登录。先用「识别」页看看它被判断成什么。

**HLS 流黑屏**
部分流要求特定的 `Referer` 或防盗链签名，浏览器带不上，就播不了。

**为什么有些网站的视频抓不到**
YouTube 有 DRM 和签名，B 站有 Referer 校验，这两类即使抓到地址也放不出来。用 `blob:` 地址播放的站点，拿到的地址离开页面就失效。

**能不能后台播放 / 锁屏播放**
网页做不到。浏览器在切到后台或锁屏时会暂停媒体，这是系统限制。

**全屏后画面是躺着的**
把手机横过来（顶部朝左），它会自动重新排版并正立铺满。iOS 上网页无法让设备强制转屏，只能把画面先转好，再由你横手机。

**全屏按钮点了没反应**
先播放一个视频再点，没加载视频时按钮是暗的，点了会提示。

**为什么全屏是"网页自己做的"**
三条限制叠在一起：iPhone 的 Safari 只允许视频本身进原生全屏，普通元素不行；主屏幕 App（PWA）里原生视频全屏只会铺满、不会像 Safari 那样转屏；Android 允许元素全屏，但多数浏览器拒绝网页锁定屏幕方向。所以做法是分环境走——Safari 用原生全屏，主屏幕模式和安卓用自绘铺满层 + 旋转 90°，横屏后自动转正。

**改了代码但打开还是旧界面**
主屏幕 App 会长期缓存页面。页面里已加了版本自检，正常情况会自动切到新版；如果仍是旧的，删掉桌面图标，用 Safari 重新打开链接后再「添加到主屏幕」。

## 五、自己部署

本地预览：

```bash
cd web
python3 -m http.server 8080
# 打开 http://localhost:8080
```

> 注意：必须通过 http/https 打开。直接双击 `index.html`（`file://` 协议）会让剪贴板、localStorage 等 API 受限，部分功能不可用。

## 六、iOS 原生 App（可编译出 .ipa）

同一套功能另有一份原生 SwiftUI 工程，在 `VideoLinker/`，共 9 个源文件。它和网页版不是替代关系，而是各有所长：

| 能力 | 网页版 | 原生 App |

| 画中画、AirPlay | 受限 | 原生支持 |

| 安装成本 | 添加到主屏幕即可 | 需要 Apple 签名 |

### 功能

三个标签：播放、列表、嗅探。

- **播放**：粘贴链接即播，支持 mp4、mov、m4v 直链与 m3u8 直播流；顶部有全屏按钮
- **列表**：可建多个播放列表，从任意一条开始顺序连播，播放页顶部显示「3 / 8」
- **嗅探**：输入网址后用内置浏览器扫描 `<video>`、`<source>`、`fetch`、`XHR` 四种来源，找到地址直接播

### 全屏是怎么实现的

`OrientationLock.swift` 用 iOS 16 的 `requestGeometryUpdate` 请求转向，这是公开接口，不是私有 API，可以正常过审。平时整个 App 锁竖屏，点全屏按钮时锁横屏并铺满，退出或把手机竖回来时自动恢复。

## 数据都存在哪

播放历史和列表存在浏览器的 `localStorage` 里，只在本机、只在这个域名下。换浏览器或清除网站数据会丢失。没有任何数据被上传。

### 原生 App（v2.7 起）

App 用 GRDB 把数据统一存在一个 SQLite 库里：`Application Support/VideoLinker/videolinker.sqlite`。

- 表：`history`（播放历史）、`resume`（观看进度）、`favorite`（收藏）、`playlist` / `playlistItem`（播放列表）、`script` / `scriptValue`（用户脚本与 GM 存储值）、`download`（下载记录）、`webVisit`（网页历史）、`bookmark`、`shortcut`
- 首次升级会把旧版 UserDefaults 里的 JSON 全量搬进库，搬之前先备份成 `legacy-backup-<时间>.json`
- 写入仍然双写 UserDefaults，装回旧版本也能看到全部数据
- 设置 → 关于 里能看到库体积；一致性校验页在 v2.7.3 移除（迁移验证完成后不再需要）

### v2.8.0 新增

- **后台下载**：直链改走 `URLSession` 后台会话（identifier `com.example.VideoLinker.downloads`），锁屏、切后台继续跑；App 被系统回收后重新打开会自动认领还在跑的任务
- **暂停 / 继续 / 重试**：下载列表每行右侧有对应按钮，暂停会尽量保存断点数据（`resumeData`），继续时接着下；HLS 不支持真断点，继续等于重下
- **并发上限**：设置 → 下载 → 同时下载数量（1–5），默认 3
- **导出**：完成的项目可导出到「文件」App、存进系统相册，或走分享面板
- **缩略图**：下载列表和播放列表的本地视频显示首帧缩略图与时长，缓存到 `Caches/VideoThumbs`
- **嗅探增强**：HLS / MP4 / 其他 分类筛选，支持多选后批量下载、批量加入「下载」列表、批量复制
- **外挂字幕**：播放页可载入 srt / vtt / ass 字幕（ass 取纯文本），本地视频会自动找同名同目录字幕；字号在设置 → 播放里调

### v2.8.1 修复

- **暂停/继续按钮**：下载行不再挂整行 `onTapGesture`，内容区与右侧按钮各自独立，点按钮不会再被行手势吃掉；按钮命中区域放大到 44pt
- **HLS 断点续传**：m3u8 改为分片级队列，已下好的分片存在 `Caches/HLSParts/<任务ID>/`，继续或重启都只补缺的那几片，不再从头下
- **后台/锁屏**：直链与分片统一走后台 `URLSession`，锁屏、切后台、被系统回收后重开都能接着跑；后台唤醒按 `taskDescription` 把分片任务认回来
- **实时速度**：下载列表每行显示 `2.4 MB/s · 34% · 12.1 MB / 40 MB`，首页下载条同步显示速度
- 后台会话超时从 60 秒放宽到 300 秒，避免锁屏后频繁失败

### v2.8.2 修复

- **下载进度乱跳**：分片任务的回调之前会把「这一小片」的字节数和百分比写到整条任务上，4 片并行时进度就在各片之间来回跳（比如 60% ↔ 22%，总量在 698 KB / 656 KB 之间变）。现在分片只上报字节，百分比统一按「已落地几片」算
- **重复任务**：同一条记录可能同时挂着旧的恢复任务和新的派发任务，两个任务轮流写字数导致数字横跳。现在只认记录当前绑定的那个任务，旧任务迟到的回调一律丢弃
- **进度只增不减**：断点续传时服务端只报剩余长度、某一片失败重排，都会让进度回退。现在总量取历史最大值，百分比加单调钳制
- **续传位置**：从系统 `resumeData` 里读出已下载字节数作为偏移量，继续后从断点接着显示，不再从 0 涨回 60%
- HLS 不再显示会变的「/ 698 KB」总量，只显示已下载量 + 百分比

### v2.8.3 修复

- **总大小**：HLS 拿不到文件总字节数，上版直接把总量藏了。现在按「已落盘分片的平均大小 × 总片数」边下边估，显示成 `75.4 MB / ≈328 MB`，片数越多越准
- **速度消失**：慢速网络下某一秒没收到字节，速度就被清零，界面上整块消失。现在连续 4 秒没有数据才归零，中间按 0.65 衰减；下载中固定占位显示，不会再缺一块
- 速度改成一阶平滑，25 KB/s 这种低速下数字不会一格一格乱蹦

### v2.9.0 新增

- **局域网收件箱**：下载页「管理 → 从电脑传文件」，或设置 → 下载 → 局域网收件箱。手机连 Wi-Fi 后开启，电脑浏览器打开 `http://手机IP:8080`，把视频拖进去就直接进「下载」列表，视频还会顺手进播放列表。不经过任何服务器，只走局域网
  - 只处理 `GET /` 和 `PUT /upload`，请求体边收边写盘，不吃内存；端口被占用会自动往后试 8081 / 8082 / 8090 / 8099
  - 首次使用会弹本地网络权限，要允许，否则电脑连不上
  - App 要在前台，iOS 不允许长期在后台开着监听
- **悬浮键一键下载**：浏览器右下角的悬浮按钮改成「短按直接下、长按挑清晰度」。短按会在这页抓到的地址里挑最像正片的那个（m3u8 优先，其次 mp4/mov，带 advert/trailer/preview 等字样的降权），不用先开列表；长按还是原来的嗅探面板
