# VideoLinker

一个 iOS 原生视频播放器。粘贴地址即播，带内置浏览器嗅探、后台下载、多播放列表、WebDAV、局域网互传与投屏，另带签到、积分和派猫猫旅行。

- 原生 SwiftUI，iOS 14 起
- 数据全部存在本机，不上传任何服务器
- 未上架 App Store，需要自己签名安装

## 安装

准备一台 Windows 或 Mac、一根数据线、一个 Apple ID，加上 `VideoLinker-unsigned.ipa`。

用 Sideloadly 签名装进手机，全程免费。免费账号签的包 **7 天有效**，到期重签一次即可，数据不会丢。

完整步骤（含信任证书、开发者模式、常见报错）见 **[安装教程.md](安装教程.md)**。

想自己出包：

| 方式 | 需要 | 说明 |
| --- | --- | --- |
| Xcode | 一台 Mac | 打开 `VideoLinker.xcodeproj`，选自己的手机按 ⌘R |
| GitHub Actions | 一个 GitHub 仓库 | 推代码自动编译，在 Artifacts 里取 ipa |

## 功能

底部五个标签：**播放、列表、签到、嗅探、设置**。

### 播放

- 粘贴地址即播，支持 mp4 / mov / m4v 直链与 m3u8 直播流
- 输入框可以直接粘一**整段分享文案**，会自动把里面的网址挑出来
- 右上角全屏按钮，系统直接把屏幕转成横屏，不用自己转手机
- 手势：上下滑调亮度 / 音量，左右滑拖进度，双击快进，长按 2 倍速
- 画中画、AirPlay 原生支持，锁屏和切后台继续播
- 外挂字幕：srt / vtt / ass，本地视频自动找同名同目录字幕，字号可调
- 右上角 ⋯ →「技术信息」：容器、编码、分辨率、帧率、码率、HDR、音轨参数，可一键复制
- 记住每条的观看进度，看到结尾按钮变「重播」

### 列表

- 可建多个播放列表，内置一个「下载」列表；从任意一条开始顺序连播
- 每行底部有 3pt 观看进度条，右侧显示「看到 42%」；在线条目自动抓网页封面
- 长按列表卡片可重命名 / 置顶 / 删除；长按视频条目可改名
- 排序：名称 A→Z、Z→A、视频多的在前、最近创建、最早创建，也能手动拖动
- 本机视频：扫描并导入 App 里的视频，支持从「文件」App 多选、iCloud 未下载的文件
- 存储管理：按大小列出文件，标出重复 / 未进列表 / 已看完，一键清理并同步删掉死条目

### 下载

- 后台下载，锁屏、切后台、被系统回收后重开都能接着跑
- 暂停 / 继续 / 重试；HLS 按分片续传，只补缺的片
- 同时下载数量 1–5
- 完成后可导出到「文件」App、存进相册或走分享面板
- 列表显示首帧缩略图、时长、实时速度与进度

### 嗅探

- 输入网址后用内置浏览器扫描 `<video>`、`<source>`、`fetch`、`XHR` 四种来源
- 结果按 HLS / MP4 / 其他分类，支持多选后批量下载、批量加入列表、批量复制
- 每行显示域名、时长、分辨率
- 右下角悬浮球短按直接抓这一页最像正片的地址

### 签到（底部五标签之一）

页面底部有三段切换：**签到、积分、旅行**。

- 多账号，国内版 `codebuddy.cn` 与国际版 `workbuddy.ai` 可切
- 一键签到，每天首次打开 App 自动补签，当天签过的不重复请求
- 积分：总积分、剩余 / 总量、最近到期，7 天内到期会标橙
- 派猫猫旅行：查状态、一键派发、到达后领奖，页面停留时每 60 秒自动刷新
- 接口路径放在 `wb-endpoints.json`，官方改路径时只改这份文件，App 重启生效，不用重新装包。设置 → 关于 →「签到接口」可查看当前配置、填自定义地址或直接粘贴导入

### 设置

- 主题（跟随系统 / 浅色 / 深色）、字幕字号
- **WebDAV 网络存储**：浏览 NAS 目录，点视频直接播，密码存系统钥匙串
- **局域网收件箱**：手机开 HTTP 服务，电脑浏览器打开 `http://手机IP:8080` 把视频拖进去
- **局域网投屏**：电脑浏览器打开 `http://手机IP:8088` 直接看手机里的视频，进度条可拖
- **观看统计**：本周 / 今天 / 累计时长、近 7 天柱状图、常看来源、看得最多的片子
- **App 锁**：面容 ID / 触控 ID，可设立即 / 1 分钟 / 5 分钟宽限
- 下载并发数、存储管理、观看统计、签到接口、关于

> 局域网收件箱和投屏需要「本地网络」权限，App 会在你打开对应页面时主动申请。

## 全屏是怎么实现的

`OrientationLock.swift` 用 iOS 16 的 `requestGeometryUpdate` 请求转向，这是公开接口，不是私有 API。平时整个 App 锁竖屏，点全屏按钮时锁横屏并铺满，退出或把手机竖回来时自动恢复。

## 数据存在哪

### v2.7.0 起：SQLite

App 用 GRDB 把数据统一存在一个 SQLite 库里：`Application Support/VideoLinker/videolinker.sqlite`。

- 表：`history`（播放历史）、`resume`（观看进度）、`favorite`（收藏）、`playlist` / `playlistItem`（播放列表）、`script` / `scriptValue`（用户脚本与 GM 存储值）、`download`（下载记录）、`webVisit`（网页历史）、`bookmark`、`shortcut`
- 首次升级会把旧版 UserDefaults 里的 JSON 全量搬进库，搬之前先备份成 `legacy-backup-<时间>.json`
- 写入仍然双写 UserDefaults，装回旧版本也能看到全部数据
- 设置 → 关于 里能看到库体积；一致性校验页在 v2.7.3 移除（迁移验证完成后不再需要）

## 版本记录

### v2.8.0 新增

- **后台下载**：直链改走 `URLSession` 后台会话（identifier `com.example.VideoLinker.downloads`），锁屏、切后台继续跑；App 被系统回收后重新打开会自动认领还在跑的任务
- **暂停 / 继续 / 重试**：下载列表每行右侧有对应按钮，暂停会尽量保存断点数据（`resumeData`），继续时接着下；HLS 不支持真断点，继续等于重下
- **并发上限**：设置 → 下载 → 同时下载数量（1–5），默认 3
- **导出**：完成的项目可导出到「文件」App、存进系统相册，或走分享面板
- **缩略图**：下载列表和播放列表的本地视频显示首帧缩略图与时长，缓存到 `Caches/VideoThumbs`
- **嗅探增强**：HLS / MP4 / 其他 分类筛选，支持多选后批量下载、批量加入「下载」列表、批量复制
- **外挂字幕**：播放页可载入 srt / vtt / ass 字幕（ass 取纯文本），本地视频会自动找同名同目录字幕；字号在设置 → 播放里调

### v2.8.1 修复

- **暂停/继续按钮**：下载行不再挂整行 `onTapGesture`，内容区与右侧按钮各自独立，点按钮不会再被行手势吃掉；按钮命中区域放大到 44pt
- **HLS 断点续传**：m3u8 改为分片级队列，已下好的分片存在 `Caches/HLSParts/<任务ID>/`，继续或重启都只补缺的那几片，不再从头下
- **后台/锁屏**：直链与分片统一走后台 `URLSession`，锁屏、切后台、被系统回收后重开都能接着跑；后台唤醒按 `taskDescription` 把分片任务认回来
- **实时速度**：下载列表每行显示 `2.4 MB/s · 34% · 12.1 MB / 40 MB`，首页下载条同步显示速度
- 后台会话超时从 60 秒放宽到 300 秒，避免锁屏后频繁失败

### v2.8.2 修复

- **下载进度乱跳**：分片任务的回调之前会把「这一小片」的字节数和百分比写到整条任务上，4 片并行时进度就在各片之间来回跳（比如 60% ↔ 22%，总量在 698 KB / 656 KB 之间变）。现在分片只上报字节，百分比统一按「已落地几片」算
- **重复任务**：同一条记录可能同时挂着旧的恢复任务和新的派发任务，两个任务轮流写字数导致数字横跳。现在只认记录当前绑定的那个任务，旧任务迟到的回调一律丢弃
- **进度只增不减**：断点续传时服务端只报剩余长度、某一片失败重排，都会让进度回退。现在总量取历史最大值，百分比加单调钳制
- **续传位置**：从系统 `resumeData` 里读出已下载字节数作为偏移量，继续后从断点接着显示，不再从 0 涨回 60%
- HLS 不再显示会变的「/ 698 KB」总量，只显示已下载量 + 百分比

### v2.8.3 修复

- **总大小**：HLS 拿不到文件总字节数，上版直接把总量藏了。现在按「已落盘分片的平均大小 × 总片数」边下边估，显示成 `75.4 MB / ≈328 MB`，片数越多越准
- **速度消失**：慢速网络下某一秒没收到字节，速度就被清零，界面上整块消失。现在连续 4 秒没有数据才归零，中间按 0.65 衰减；下载中固定占位显示，不会再缺一块
- 速度改成一阶平滑，25 KB/s 这种低速下数字不会一格一格乱蹦

### v2.9.0 新增

- **局域网收件箱**：下载页「管理 → 从电脑传文件」，或设置 → 下载 → 局域网收件箱。手机连 Wi-Fi 后开启，电脑浏览器打开 `http://手机IP:8080`，把视频拖进去就直接进「下载」列表，视频还会顺手进播放列表。不经过任何服务器，只走局域网
  - 只处理 `GET /` 和 `PUT /upload`，请求体边收边写盘，不吃内存；端口被占用会自动往后试 8081 / 8082 / 8090 / 8099
  - 首次使用会弹本地网络权限，要允许，否则电脑连不上
  - App 要在前台，iOS 不允许长期在后台开着监听
- **悬浮键一键下载**：浏览器右下角的悬浮按钮改成「短按直接下、长按挑清晰度」。短按会在这页抓到的地址里挑最像正片的那个（m3u8 优先，其次 mp4/mov，带 advert/trailer/preview 等字样的降权），不用先开列表；长按还是原来的嗅探面板

### v3.0.0 新增

- **App 锁**：设置 → 隐私。打开后进入 App 或从后台切回来要过面容 ID / 触控 ID（识别不了可退回设备密码）。可设「立即 / 1 分钟 / 5 分钟」宽限期，出厂默认立即；切后台时先盖一层纯色，多任务截图里看不到内容。用 `LocalAuthentication` 的 `.deviceOwnerAuthentication`，设备上没设密码时自动放行，不会把人锁在外面
- **观看统计**：设置 → 数据 → 观看统计。本周 / 今天 / 累计时长、近 7 天柱状图、常看来源（按域名聚合）、看得最多的片子（点一下直接播）、以及「下了没看」——下载记录里有但一次都没打开过的文件，连大小一起列出来。数据存在 `watchSession` 表（v2 迁移），按次记录、读的时候再聚合，清空统计不影响观看进度和播放历史
- **WebDAV 网络存储**：设置 → 网络存储。填地址 + 账号密码就能浏览 NAS 上的目录，点视频直接播，不用先下载到手机。`PROPFIND Depth:1` 列目录，自写 XML 解析，不引第三方库；密码进系统钥匙串，不落配置文件
  - 播放走 `AVURLAsset` 的 `AVURLAssetHTTPHeaderFieldsKey` 带 `Authorization`，HLS 分片请求也会继承；VLC 兜底时改传 `:http-user` / `:http-pwd`
  - 仅 WebDAV。SMB / AFP 要额外的系统组件，这一版没做

### v3.1.0 修复与调整

- **播完可直接重播**：把片子看到结尾后，中间的大按钮变成「重播」图标，点一下从 0 秒重新开始，不再出现「点了没反应」。往回拖进度条会退回到播放/暂停按钮
- **音量提示**：播放页里藏着一个 1×1 的 `MPVolumeView`（滑动手势改音量要用它），系统自带的音量 HUD 因此不会出现。现在改为监听 `AVAudioSession.outputVolume`（并用滑块 `value` 兜底），按手机侧键时在顶部弹一条自己画的提示：喇叭图标 + 进度条 + 百分比，1.3 秒后自动消失
- **悬浮球改为开结果页**：点右下角悬浮球不再替用户盲下一条地址，统一打开嗅探结果页自己挑；长按的「挑清晰度」逻辑一并去掉，短按就够了
- **嗅探结果补时长和分辨率**：每行第二行从「域名」变成「域名 · 12:34 · 1920×1080」。先用 `AVURLAsset` 读 duration 和 `naturalSize`（按 `preferredTransform` 摆正竖屏视频），读不到就把 m3u8 当文本解一遍：master 里按 RESOLUTION 选最高码率那档，再累加 `#EXTINF` 算总时长。9 秒没结果就放弃，同一地址只探一次，最多并发 3 条

### v3.1.1 修复与新增

- **上下滑调音量不再误触快进**：三个原因一起修——① 方向判定原本是「宽高谁大」，斜着划一帧就锁成快进，现在要拉开 1.5 倍余量才锁定；② 上一次拖动若被系统打断没收到 `onEnded`，`dragMode` 会留在「快进」上，下一次上下滑就跟着跳进度，现在按起点位置识别新手势、每轮重新判定；③ 慢慢上下滑超过 0.6 秒会触发长按 2 倍速，看起来也像快进，现在一判定成拖动就取消长按、已在 2 倍速的直接退出
- **刚调完音量不响应双击快进**：连着两下上下划很容易被认成双击，0.7 秒内直接忽略
- **本机视频**：首页新增「本机视频」入口（播放列表页右上角菜单里也有）。扫描 App 文档目录里的所有视频，分「发现」和「已在列表」两段显示，带缩略图、时长、大小；点一下直接播，右侧加号加入播放列表，底部可以「全部加入」
- **添加本地视频**：同一页右上角「导入」，从「文件」App 里多选视频（含音频），复制进 Downloads 目录后自动登记到下载列表和播放列表；本来就在 App 文件夹里的文件是移动而不是复制，不会留下两份
- `UIFileSharingEnabled` + `LSSupportsOpeningDocumentsInPlace`：打开后「文件」App 里能看到「我的 iPhone → VideoLinker」，电脑用 Finder / iTunes 文件共享也能把视频直接拖进来，再回来自动扫到

### v3.3.0 修复与新增

- **修「导入视频点打开没反应」**：原来用 SwiftUI 的 `.fileImporter`，视图本身就在 sheet 里，再叠一层系统文件选择器时回调会丢，表现就是选完文件点「打开」界面毫无变化。改成自己拿 top view controller 弹 `UIDocumentPickerViewController`，回调稳定；同时补了导入进度浮层（「正在导入 xxx」），大文件复制期间不再像卡死
- **iCloud 文件也能导**：iCloud Drive 里没下载到本机的文件，`copyItem` 会直接失败。现在先 `startDownloadingUbiquitousItem` 等它落盘（最多 45 秒），再用 `NSFileCoordinator` 协调读取
- **导入结果说清楚**：以前只有「已添加 N 个」；现在区分「已导入 / 已在列表 / 读不出来」，选到已经在列表里的文件不会再静默无反应
- **行内观看进度条**：播放列表每一行底部一条 3pt 细进度条，右侧显示「看到 42%」；看完整条变灰，扫一眼就知道哪些快看完了
- **在线视频封面**：列表里的在线条目不再只是序号，会异步抓网页的 `og:image` / `twitter:image` 当封面，落盘缓存、同址只抓一次；抓不到（直链视频、需要登录的页面）自动回落到序号
- **存储管理**：设置 → 数据 → 存储管理。顶部显示已占用 / 设备可用 / 可释放空间，文件按大小倒序，标出「重复」「未进列表」「已看完」；支持清理重复文件（同尺寸每组保留最早的一个）和清理已看完的，删除时同步清理下载记录与播放列表里的死条目

### v3.3.1 修「导入没反应」和「视频没进播放列表」

- **导入选择器换实现**：前两版分别栽在 `.fileImporter` 回调和自己找 top view controller 上。这版把呈现权交给 SwiftUI——sheet 里放一个空宿主控制器，在 `viewDidAppear` 里弹 `UIDocumentPickerViewController`，生命周期由 SwiftUI 管，delegate 由宿主强持有
- **选择器一律 `asCopy: true`**：系统会先把文件（包括 iCloud 里还没落盘的）复制到 App 临时目录，拿到的 URL 立刻可读。iCloud 占位、安全作用域、文件提供方权限这三类失败一并绕开，导入完再把临时副本删掉
- **导入不再重复复制**：列表里已有同名文件时直接算「已在列表」，不会在 Downloads 里多出一份 `master 2.ts`
- **修「视频显示已在列表，但播放列表里没有」**：之前判断「已在列表」时把下载记录也算进去了，导致文件卡在「不能加、也没在列表」的死结。现在只认播放列表

### v3.4.1 修「没有本地网络权限弹窗、设置里也没有开关」

- **根因**：iOS 的本地网络授权**只在特定动作时才弹窗**——Bonjour 浏览/广播、组播广播、主动连接局域网地址。只开一个 TCP 监听端口是**不会**弹的，于是权限一直停在「未决」：服务起得来、地址也显示，但电脑连不上，设置里也找不到开关
- Info.plist 补上 `NSBonjourServices`（`_videolinker._tcp`），权限说明文案改成同时覆盖投屏和收件箱
- 新增 `LocalNetworkPermission`：用一次 `NWBrowser` 的 Bonjour 浏览触发系统弹窗，并按 `-65555`（PolicyDenied）判断 granted / denied / 超时
- 投屏页新增「本地网络权限」卡片：显示当前状态、一键申请；被拒时直接给出设置路径（iOS 18 起在 隐私与安全性 → 本地网络，iOS 17 及更早在 App 自己的设置页）
- 打开投屏页就先问一次权限，不用等开了服务才发现电脑连不上
- 服务起来后自动**端到端自检**：App 自己去请求 `http://手机IP:端口/ping`。通过说明端口和权限都正常；失败会提示先查权限，而不是让用户对着地址干猜
- 局域网收件箱启动时也顺手触发一次授权（同一个权限，两边共用）
- 超时（25 秒）只提示「没有响应」，**不取消 Bonjour 浏览**——弹窗可能还挂在屏幕上，这时取消会把弹窗一起收掉，用户就没机会点「允许」了；等用户点了，状态会自动变成「已允许」并重跑自检
